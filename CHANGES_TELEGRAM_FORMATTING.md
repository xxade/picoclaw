# Изменения: расширенное форматирование Telegram

Ветка: `feature/telegram-extended-formatting` (форк xxade/picoclaw, base = upstream sipeed bbf6893c).

## Сделано

### 1. Rich-сообщения Telegram (главное)
Telegram с Bot API 10.1 (июль 2026) поддерживает «богатые сообщения»
(`sendRichMessage`): клиент сам рендерит нативные таблицы, заголовки H1–H6,
списки задач, сворачиваемые блоки `<details>`, цитаты. Канал теперь шлёт
исходный markdown туда без конвертации — это и есть «настоящие таблицы» в
Telegram. Реализовано:

- `pkg/channels/telegram/rich.go` — отправка (`sendRichText` с reply),
  правка (`editRichMessage` через `rich_message` в `editMessageText`),
  предварительная проверка лимитов (`richContentUnsupported`: >20 колонок в
  таблице, >32768 символов), классификация ошибок rich-парсера
  (`richParseFailure`).
- `Send()`: для каждого чанка сначала проба rich; при отказе Telegram —
  падение в устаревший конвейер; сетевые ошибки не провоцируют повтор.
- `EditMessage()`: та же схема.
- Стриминг: черновики через `sendRichMessageDraft`, финал — rich с запасным
  вариантом HTML/обычным текстом (`telegramStreamer.rich`).
- Служебные сообщения инструментов идут по-старому (там важна длина после
  разбора).
- Флаг конфига `rich_format` (по умолчанию включён; env
  `PICOCLAW_CHANNELS_TELEGRAM_RICH_FORMAT`). Для старых клиентов, не знающих
  rich-сообщения, — выключить.
- telego v1.10.0 (уже в зависимостях) rich-API поддерживает, деп не менялся.

### 2. Запасной конвейер: таблицы GFM (fallback-путь)
Когда rich выключён или Telegram отверг содержимое:

- `table.go` — распознаватель таблиц GFM (выравнивание `:---:`, экранирование
  `\|`, пустые ячейки, строки разной ширины, игнор внутри блоков кода) и
  рендер: псевдографика Unicode в блоке кода (ширины колонок через
  go-runewidth — кириллица/CJK/emoji), автораскат в карточки «поле: значение»
  при ширине > `table_max_width` (60).
- `parseContentWithTables` — единая точка: таблицы → свёртка `<details>` →
  вырезание лишних HTML-тегов → флажки → разбор HTML/MarkdownV2.
- Поля конфига `table_mode` (авто/код/список/выкл), `table_max_width`.

### 3. Починка разбора MarkdownV2
- Реальный вывод модели (шпаргалка по CAN, тестовый файл `can_cheatsheet.md`)
  в режиме MarkdownV2 Telegram
  отвергал (`Character '.' is reserved`): цитаты передавались дословно, и
  незаэкранированная точка внутри цитаты валила всё сообщение → канал молча
  скатывался в обычный текст. Цитаты теперь экранируются как обычный текст,
  конечный маркер `||` неразвёрнутой цитаты сохраняется.
- Заголовки/выделение больше не применяются внутри блоков кода (защита
  «```» и `\`…\`` до преобразований).

### 4. Мелкое по HTML-конвейеру
- `reBlockquote` получил `(?m)` — цитаты обрабатываются на всех строках,
  а не только на первой.
- Курсив `*звёздочки*`, флажки `- [x]`/`- [ ]` → ✅/⬜.

## Открытые вопросы
- Старые клиенты (до rich-сообщений) показывают rich-сообщения обычным
  текстом. Нужна ли авто-подстройка по версии клиента — API не сообщает её,
  так что оставлен только ручной `rich_format: false`.
- Правки через rich применяются и к сообщениям, отправленным старым путём
  (Telegram принимает); односторонняя миграция формата, откат не предусмотрен.
- Подписи медиа (до 1024) идут по-старому: у `send*`-методов медиа поля
  rich_message нет.
